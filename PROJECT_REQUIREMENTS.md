# Project requirements

## README publication requirement

The root `README.md` is the judge-facing Pikul submission artifact. It must contain the problem, target users, ideation evidence, diagrams, final prototype captures, public prototype/repository links, differentiators, technical stack, method, limitations, impact, contribution table, and setup instructions. A judge must not need a PDF, Word file, or internal `docs/` note to score the work.

## Evidence rules

- README visuals are stored in `docs/readme-assets/` and embedded directly in the root README.
- Claims must be traceable to the frozen source, a public first-party source, or explicitly labelled team design evidence.
- Do not claim mentor or external-user validation before it occurs.
- Pikul measures weighted commitments against a personal baseline; it does not diagnose stress, burnout, or wellbeing.
- The current prototype has no backend, database, accounts, integrations, AI runtime, or medical function.

## Remaining submission inputs

Video, Figma/design, and slide links are omitted until public signed-out URLs are available. Screen-reader and physical-device validation remain incomplete.
